# Problem Statement Outline (Template Copy)

Use this outline when starting a new iteration of the problem statement.

1. **Context Snapshot**
   - Product overview (what, who, where).
   - Legacy system risks.
   - Desired deployment model.

2. **Pain Points**
   - Documentation or process issues (Word/PDF sprawl, manual audits).
   - Developer workflow friction.
   - Quality evidence gaps.

3. **Regulatory Drivers**
   - EN 62304 baseline (note safety class placeholder if unknown).
   - AAMI TIR45 for Agile alignment.
   - Other applicable standards (ISO 13485, IEC 62366-1) if relevant.
   - Cybersecurity scope (mark as outstanding if undecided).
   - Patient data handling (highlight current exclusion + future pathway).

4. **Project Landscape**
   - Templum role.
   - Phoenix Code Lite role.
   - Haruspex role.
   - Validation System role.
   - Any external systems.

5. **Core Problem Statement**
   - "We must … so that … despite …" formulation.

6. **Scope & Constraints**
   - In scope now.
   - Deferred/unscoped items.
   - Tooling assumptions.

7. **Success Signals**
   - Top-level outcomes that indicate success.

8. **Open Questions**
   - Missing data, approvals, or decisions.
   - Owners / follow-up plans.

## 📊 Command Customization Guidelines

### Flag Selection by Phase Complexity

**Analysis Phase (1)**:

- Use `--think-hard` for comprehensive analysis
- Include `--delegate auto` for component discovery
- Add `--persona-architect` for architectural focus
- Consider plan mode for pure analysis tasks

**Foundation Phases (2-3)**:

- Use `--think` for balanced analysis
- Include `--with-tests` for critical components
- Add `--safe` for conservative implementation
- Use `--loop` for iterative refinement

**Transformation Phase (4)**:

- Use `--think-hard` for complex backend separation
- Include `--persona-backend` for API expertise
- Add `--delegate auto` for large-scale changes
- Consider `--all-mcp` for comprehensive coordination

**Enhancement Phase (5)**:

- Include `--magic` for UI component generation
- Use `--persona-frontend` for UI-focused development
- Add `--iterative` for progressive enhancement
- Include visual design considerations

**Validation Phase (6)**:

- Use `--play` for comprehensive testing
- Include `--persona-qa` for quality focus
- Add `--type all --coverage` for complete testing
- Use `--delegate auto` for distributed testing

### When to Use Plan Mode

✅ **Recommended for Plan Mode**:

- Phase 1 (Component Extraction & Analysis)
- Architecture design commands
- Initial analysis of complex problems
- Documentation and planning tasks

❌ **Regular Mode Required**:

- Phase 2-6 (Implementation phases)
- Code generation and modification
- Testing and validation
- File creation and editing

### Command Sequencing Patterns

**Analysis → Design → Implementation**:

```bash
# 1. Analyze current state
/sc:analyze current-phase-file.md --plan-mode

# 2. Design solution architecture  
/sc:design solution-architecture --type architecture

# 3. Implement with validation
/sc:implement solution --with-tests --safe
```

**Iterative Implementation Pattern**:

```bash
# 1. Implement core functionality
/sc:implement core-feature --safe

# 2. Iterate with improvements
/sc:improve core-feature --loop

# 3. Validate with testing
/sc:test core-feature --coverage
```

## 🔧 Integration Guidance

### SuperClaude + Claude Code Native Integration

**Key Benefits**:

- Native slash command support (`/sc:` commands work directly)
- Plan mode compatibility for analysis phases
- MCP server integration for enhanced capabilities
- Automatic persona activation based on context

**Best Practices**:

1. **Use plan mode** for analysis and design phases
2. **Switch to regular mode** for implementation
3. **Leverage MCP servers** (Context7, Sequential, Magic, Playwright)
4. **Chain commands** for complex workflows
5. **Use delegation** for large-scale operations

**Command Chaining Example**:

```bash
# Phase transition workflow
/sc:analyze Phase-01-*.md --plan-mode         # Analysis in plan mode
# → Switch to regular mode
/sc:design templum-architecture               # Design phase
/sc:implement templum-core --safe             # Implementation
/sc:test templum-core --coverage              # Validation
```

**Troubleshooting**:

- If commands don't work, verify `.claude/commands/` directory setup
- Use `--help` flag to see available options for each command
- Start with simpler scopes before attempting system-wide operations
- Use `--preview` or `--plan` flags to see what will be executed

# Haruspex Agent-Debugging Architecture - Implementation Plan

> **Created**: 2025-08-15  
> **Purpose**: Comprehensive agent-debugging architecture for immediate feedback loops  
> **Status**: Design Complete - Ready for Implementation

## Architecture Overview

This document outlines a comprehensive agent-debugging architecture that provides immediate feedback loops for AI agents to inspect, debug, and interact with the Haruspex extension in real-time.

### Problem Statement

- **Current Issue**: Extension loads but WebView panes stuck in loading state due to core engine initialization issues
- **Need**: Immediate/near-immediate feedback loop for iterative agent development  
- **Constraint**: Must not disrupt existing VSCode integration

### Solution Architecture

The architecture provides:

1. **Real-time IPC communication** between agents and VSCode extension
2. **Comprehensive CLI interface** for external debugging and control
3. **State inspection system** with live monitoring and change detection
4. **Interactive control system** with automated triggers and workflows
5. **Minimal risk integration** that leverages existing infrastructure

## System Components

### 1. IPC Communication Protocol (`src/debugging/ipc-protocol.ts`)

**Purpose**: Inter-process communication bridge between agent CLI and VSCode extension

**Key Features**:

- Unix domain socket communication via `.haruspex/haruspex-debug.sock`
- Request/response pattern with timeout handling
- Real-time event subscription and broadcasting
- Automatic connection management and retry logic
- JSON message protocol with comprehensive error handling

**API Surface**:

```typescript
// Server-side (VSCode Extension)
class HaruspexIPCServer {
  async start(): Promise<void>
  async stop(): Promise<void>
  private handleClientMessage(clientId: string, data: Buffer): Promise<void>
  private executeCommand(request: CommandRequest): Promise<CommandResponse>
  private broadcastStateChange(event: StateChangeEvent): void
}

// Client-side (Agent CLI)
class HaruspexIPCClient {
  async connect(options?: ConnectionOptions): Promise<void>
  async disconnect(): Promise<void>
  async sendRequest<T>(type: IPCMessageType, payload?: any): Promise<T>
  async subscribeToEvents(eventTypes: string[]): Promise<void>
}
```

### 2. CLI Interface (`src/debugging/haruspex-cli.ts`)

**Purpose**: Comprehensive command-line interface for real-time debugging and interaction

**Command Categories**:

- **Data Operations**: `refresh`, `export`, `backup`
- **Command Execution**: `exec <command>`, with full argument and option support
- **Event Monitoring**: `watch`, with real-time event streaming
- **Interactive Mode**: `interactive`, full CLI session with contextual commands
- **Diagnostics**: `diagnose`, automated issue detection and fixing
- **PCL Integration**: `analyze-workspace`, `run-tdd`

**Usage Examples**:

```

- **Automatic change detection** with significance scoring (low/medium/high/critical)
- **Property-level watching** with conditional triggers
- **Performance trend analysis** with memory and response time tracking
- **Historical state management** with configurable retention

**State Monitoring**:

```

   if (coreEngine && debugManager) {
     try {
       ipcServer = new HaruspexIPCServer(coreEngine, debugManager, workspaceRoot);
       await ipcServer.start();
       context.subscriptions.push({ dispose: () => ipcServer?.stop() });

## Integration Strategy

### Minimal Risk Approach

**Core Principle**: All agent-debugging functionality is additive and optional. If any component fails, the extension continues to work normally.

**Implementation Pattern**:

```typescript
// All integrations use this pattern
try {
  // Initialize agent debugging component
  const component = new AgentDebuggingComponent(...);
  await component.initialize();
  
  // Register for cleanup
  context.subscriptions.push(component);
  
  debugManager.log('Agent debugging component initialized');
} catch (error) {
  debugManager.log(`Agent debugging component failed: ${error}`, 'warn');
  // Continue normal operation - no disruption
}
```

### Fallback Mechanisms

**IPC Server Failure**:

- Extension loads normally without IPC capability
- CLI shows helpful error message with troubleshooting steps
- All debugging remains accessible via VSCode commands

**State Inspector Failure**:

- IPC server continues with basic functionality
- CLI can still execute commands but without real-time monitoring
- Manual refresh commands still work

**Interactive Controller Failure**:

- IPC and state inspection continue working
- Manual command execution still possible
- Automated triggers are disabled

### Security Considerations

**Command Execution**:

- Whitelist of allowed commands only
- No arbitrary code execution
- All commands go through existing extension validation
- User confirmation required for destructive operations

**IPC Communication**:

- Local Unix domain socket only (no network exposure)
- Socket file in workspace `.haruspex` directory
- Automatic cleanup on extension deactivation
- No sensitive data transmitted (debug info only)

**File Access**:

- Limited to workspace directory and `.haruspex` subdirectory
- No access to user files outside workspace
- Debug reports exported to user-specified locations only

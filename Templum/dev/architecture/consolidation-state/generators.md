# Markdown Generators — Draft Specification

## Purpose

Translate the canonical registry (`consolidation-state.json`) into the existing Markdown artefacts so agents still have rich, human-readable references:

- Pattern plan files: `Templum/dev/architecture/utility-consolidation-plans/pattern-<id>.md`
- Global tracker: `Templum/dev/architecture/safe-consolidation-candidates.md`
- Activity log: `Templum/dev/architecture/utility-consolidation-activity-log.md`

## Generation Pipeline

1. Load and validate registry via `ajv` + schema.
2. Produce intermediate view models:
   - `patternView`: combines registry entry with static template (Stage 1 intent, coordination notes). Allows inclusion of optional free-form sections from sidecar Markdown if needed.
   - `trackerView`: summarises status per pattern (current stage, outstanding lanes, dependencies, next action).
   - `activityView`: chronological list of activity entries expanded into Markdown sections.
3. Render templates using `handlebars` (or `eta`, whichever is lighter). Templates live under `Templum/dev/architecture/consolidation-state/templates/` and compile to Markdown.
4. Write outputs to their respective files; compare with existing content to avoid no-op rewrites.
5. Exit non-zero if outputs differ but `--check` flag used (CI dry-run).

## Pattern Plan Rendering

- Keep the narrative Stage 1/guardrail text from current plans by splitting the plan file into two sections:
  1. **Static front matter**: generated from registry (Stage statuses, lane tables, approvals, command evidence).
  2. **Free-form appendix**: optional Markdown under `Templum/dev/architecture/consolidation-notes/pattern-<id>.md`. Agents can edit the appendix directly; generator injects it at the end.
- Stage 6 lanes rendered as tables summarising commands, status, and last execution timestamp. Completed lanes get ✅ icon for quick scan.
- When lane is `pending`, generator lists gating dependencies (pulled from schema) in a warning block.

## Tracker Rendering

- Replaces manual bullet lists with a table of patterns.
- Columns: Pattern ID, Stage, Lanes (badge counts), Dependencies (with status), Last Updated, Next Action (derived from first incomplete lane or stage gate).
- Include footnotes linking back to pattern plan anchors.

## Activity Log Rendering

- Sort `activity` entries across all patterns by timestamp descending.
- Group by date -> pattern -> stage.
- Auto-text derived from summary field; include bullet list of evidence paths and touched files if provided.
- Append a generator signature comment `<!-- generated by consolidation-state -->` to discourage manual edits.

## CLI Integration

- Expose generator module as `generateViews({ registryPath, outputDir, checkOnly })` so CLI can call `generateViews` after state updates.
- Provide standalone script `npm run consolidate -- regen` for manual use.
- Add pre-commit hook (optional) to ensure Markdown views are up-to-date when registry changes.

## Testing Strategy

- Snapshot tests for each template comparing expected Markdown against fixture registry state.
- Schema validation ensures view models pass required invariants (e.g., Stage 6 lane summary includes at least one command).
- CLI integration test runs `update-lane` on a fixture repo and asserts generator output for the touched pattern/tracker/activity log.

# Problem Statement Outline (Template Copy)

Use this outline when starting a new iteration of the problem statement for aligning internal tooling with VDL2’s regulated delivery needs.

1. **Context Snapshot**
   - VDL2 product overview (what, who, where).
   - Legacy system risks and why an upgraded toolset is required.
   - Desired deployment model for the product and supporting tooling.

2. **Pain Points**
   - Documentation or process issues (Word/PDF sprawl, manual audits).
   - Developer workflow friction caused by the current tooling or lack thereof.
   - Quality evidence gaps that jeopardise VDL2 compliance.

3. **Regulatory Drivers**
   - EN 62304 baseline (note safety class placeholder if unknown).
   - AAMI TIR45 for Agile alignment.
   - Other applicable standards (ISO 13485, IEC 62366-1) if relevant.
   - Cybersecurity scope (mark as outstanding if undecided).
   - Patient data handling (highlight current exclusion + future pathway).

4. **Project Landscape**
   - Templum role in supporting compliance workflows.
   - Phoenix Code Lite role as QMS workflow engine.
   - Haruspex role in analysis/insight generation.
   - Validation System role in evidence capture.
   - Any external systems that interact with the tooling.

5. **Core Problem Statement**
   - "We must … so that … despite …" formulation focused on tooling enabling VDL2 success.

6. **Scope & Constraints**
   - In scope now (tooling changes, workflows).
   - Deferred/unscoped items (patient data, cybersecurity specifics, third-party tools).
   - Tooling assumptions (docs-as-code, skin-driven UI, etc.).

7. **Success Signals**
   - Top-level outcomes that indicate the tooling is supporting VDL2 effectively.

8. **Open Questions**
   - Missing data, approvals, or decisions.
   - Owners / follow-up plans.
